## CHANGE SET A · The `"On "` prefix — 3 files to repair, 3 to harden

### Why

`apps/backend/src/handlers/bid-form/getBidForm.ts` now emits:

```
"Supplier"  →  "On Supplier"
"Renter"    →  "On Renter"
```

on `deliveryBy`, `returnBy`, and the `requiredTerms` party values (`fuel`, `fatFood`,
`fatTransport`). Every reader of that payload tests for equality against the bare word.
`"On Supplier" !== "supplier"`, so each one silently falls through to its default branch. Where that
branch is a label, the raw ENGLISH string is printed — on the Arabic form too, because the endpoint
sends no Arabic twin for these and the web localises them itself through `PARTY_VALUES`. Where it is
a boolean (`delBySup`), the form concludes the *other party* owns the leg.

### ⚠️ Scope — read this before doing A4–A6

The same commit changed `quotation.service.ts`, but **those values never reach the web**. I checked:
`responsibilityEn` / `responsibilityAr` / `localizeTermValueEn` / `localizeTermValueAr` are private
to that file (not exported, no other caller) and are used only to render the **backend's own
quotation PDF**, at `quotation.service.ts:888/896/898` and `:1773/1806`. The prefix and the Arabic
«على المورد» are the intended wording *on that document*. The deal-room API sends term values raw.

Its `term-matching.ts` edit was a label only — `Breakdown SLA` → `Breakdown Response SLA` and its
Arabic — not a value.

So:

| Edit | Kind | Why |
|---|---|---|
| **A1, A2, A3** | **Repair** | They read `GET /public/bid-form/{token}`, which is where the prefix actually arrives. |
| **A4, A5, A6** | **Hardening** | They read raw enums today (`deal-room` term values, `bid.requestTerms.maintenanceResponsibility` off the request payload). Nothing is broken. Doing them costs three lines and makes the next such rename harmless; skipping them changes nothing visible. **Do not describe them as bug fixes in the commit message.** |

If you are cutting the smallest possible hotfix, **A1 + A2 + A3 + A7 is the whole repair**.

### A1 · `src/lib/contract/labels.ts` — add the shared normaliser

**Find** (line 84):

```ts
export const responsibilityLabel = (v: string, L: LFn): string => lookup(RESPONSIBILITY, v, L);
```

**Replace with:**

```ts
export const responsibilityLabel = (v: string, L: LFn): string => lookup(RESPONSIBILITY, partyToken(v), L);

/**
 * A responsibility value with the endpoint's display prefix taken off.
 *
 * ⚠️ **`GET /public/bid-form/{token}` changed its VALUES on 2026-09-02**, not just its labels
 * (app commit `c304828a`): `deliveryBy`, `returnBy` and `requiredTerms.fuel` now read
 * `"On Supplier"` / `"On Renter"` where they read `"Supplier"` / `"Renter"` before, and
 * `quotation.service.ts` / `term-matching.ts` did the same to the maintenance and
 * cost-responsibility values. Every reader compared the two old words exactly, so the new spelling
 * matched nothing and fell through to the branch meaning *the other party*.
 *
 * Both spellings stay valid and both must keep working: an older backend still sends the bare
 * tokens, and so do surfaces that build their items locally. So this STRIPS the prefix rather than
 * remapping the value, leaving every existing comparison and lookup keyed exactly as it was.
 *
 * The Arabic «على » is deliberately NOT stripped: those values arrive as finished display text and
 * are printed, not compared.
 *
 * Returns "" for null/undefined, so a caller can compare without a null check — the same shape the
 * `(v || "").toLowerCase()` idiom it replaces already had.
 */
export function partyToken(v: string | null | undefined): string {
  return String(v ?? "").trim().replace(/^on\s+/i, "");
}
```

⚠️ The regex is anchored and requires the space. `"Onsite crew"` and `"Owner"` must come back
unchanged — there is a test for this in A7.

## CHANGE SET B · The overtime `'0'` sentinel — 9 files

string**. The app's own backend now normalises it away in four places because it was printing
"Overtime 0 SAR/hr" on signed quotations and raising a permanent phantom conflict in the deal room.
The web both writes it and reads it back.

restore. Follow that.

## CHANGE SET E · OTP autofill on Android — inert until backend

`main` already has `autoComplete="one-time-code"` on the first box
(`src/components/auth/CodeEntry.tsx:157`, and again in `profile/ChangePhoneModal.tsx:155`). That is
the iOS half and it works. Android needs the WebOTP API.

In `CodeEntry.tsx`, add `useEffect` to the React import and insert before `resetBoxes`:

```tsx
  /**
   * **WebOTP — the browser reads the SMS itself** (Chrome on Android; a no-op everywhere else).
   *
   * ⚠️ **Inert until the SMS carries the binding line.** WebOTP only fires for a message whose LAST
   * line is `@<origin-host> #<code>` — e.g. `@moedatech.net #1234`. Without it the promise never
   * resolves, which is why this is safe to ship first. `autoComplete` above stays: the two
   * mechanisms are independent.
   */
  useEffect(() => {
    if (typeof window === "undefined" || !("OTPCredential" in window)) return;
    const ac = new AbortController();
    navigator.credentials
      .get({ otp: { transport: ["sms"] }, signal: ac.signal } as CredentialRequestOptions)
      .then((cred) => {
        const otp = (cred as { code?: string } | null)?.code?.replace(/\D/g, "").slice(0, 4);
        if (!otp) return;
        setBoxes([0, 1, 2, 3].map((i) => otp[i] ?? ""));
        inputs.current[Math.min(otp.length, 3)]?.focus();
      })
      .catch(() => {
        /* aborted, dismissed, or unsupported — the renter types it, exactly as before */
      });
    return () => ac.abort();
  }, []);
```

Adjust `slice(0, 4)` and the box count if prod uses a 6-digit code.

### E2 · `src/components/profile/ChangePhoneModal.tsx` — the same input, a second time

`main` has a **second** four-box code entry at line 155, with its own `autoComplete="one-time-code"`
and its own copy of the paste/focus logic. A renter changing their phone number hits the same Android
gap as one signing in.

Either add the same `useEffect` there, or — better — lift the four-box entry into one shared
component so the next fix lands once. Two hand-maintained copies of an OTP input is how they drift.

⚠️ If you add the effect to both, only one may be **mounted** at a time. Two live
`navigator.credentials.get({otp})` listeners is undefined behaviour in Chrome. The `AbortController`
cleanup covers it as long as the modal truly unmounts rather than merely hiding — check that.
